# Documentación Capstone

La documentación del proyecto se organiza por propósito para mantener trazabilidad académica y técnica.

```text
docs/
├── 00_contexto/
├── 01_fase_1_definicion/
│   ├── equipo/
│   ├── fernando/
│   ├── juan/
│   └── david/
├── 02_fase_2/
├── 03_fase_3/
├── gestion/
├── arquitectura/
└── evidencias/
```

## Criterio de almacenamiento

- `00_contexto`: antecedentes del proyecto, empresa, problema y material de referencia autorizado.
- `01_fase_1_definicion/equipo`: entregables grupales de la definición del Proyecto APT.
- `01_fase_1_definicion/<integrante>`: autoevaluaciones, diarios de reflexión y otros entregables individuales.
- `02_fase_2` y `03_fase_3`: entregables de fases posteriores.
- `gestion`: planificación, metodología, riesgos, reuniones y seguimiento.
- `arquitectura`: decisiones, diagramas y especificaciones técnicas.
- `evidencias`: evidencias verificables del desarrollo y pruebas.

## Regla de colaboración

Cada integrante trabaja en su rama `dev/<nombre>`. Los documentos o cambios consolidados pasan a `main` mediante Pull Request revisado por otro integrante.
